# Patches

Every file in this directory is a unified diff against the pinned upstream
commit listed in `Build/versions.env`. The build script applies them in
lexical order with `git apply --3way` before configuring CMake. Each patch is
kept as small as possible so that it can be proposed upstream unchanged.

| Patch | Target | Rationale | Upstream status |
|---|---|---|---|
| `0001-baresip-account-contact-uri-params.patch` | baresip v4.9.0 | libre already supports Contact URI parameters on REGISTER through `sipreg_set_contact_params()`, but baresip never calls it and offers no public setter. The patch adds `account_set_contact_params()` / `account_contact_params()` and wires the value into `reg_register()` so every REGISTER (initial, auth retry, refresh, re-register after a token update, unregister) carries the parameters inside the Contact URI. | to be proposed |
| `0002-baresip-avcapture-cmake-ios.patch` | baresip v4.9.0 | `modules/avcapture/CMakeLists.txt` only enables the module when `CMAKE_SYSTEM_NAME` is `Darwin`. An iOS cross-build sets `CMAKE_SYSTEM_NAME=iOS`, so the AVFoundation capture module was silently dropped from iOS builds. The patch accepts `iOS` as well. The module also contains macOS-only API (`AVCaptureScreenInput`), handled by 0003, and uses manual reference counting; see the feasibility report for why BaresipKit ships its own capture source anyway. | to be proposed |
| `0003-baresip-avcapture-ios-screen-input.patch` | baresip v4.9.0 | With 0002 the module is compiled for iOS and fails against the iOS SDK: `'AVCaptureScreenInput' is unavailable: not available on iOS` (`avcapture.m:26`, `:216`, `:316`). The patch guards the screen-capture parts with `TARGET_OS_IPHONE`, in the style the file already uses for the macOS-only presets: the ivar is typed `AVCaptureInput *` on iOS, the two `AVCaptureScreenInput` allocations and the `screen` device registration are compiled only for macOS. On iOS, opening `screen` returns no source instead of crashing; macOS behaviour is unchanged. | to be proposed |

| `0004-re-tls-verify-server-handler.patch` | libre v4.9.0 | libre verifies server certificates with OpenSSL's default callback and offers no hook for the client side. The patch adds `tls_set_verify_server_handler()`, which receives OpenSSL's pre-verification result, the chain depth and the certificate in DER form for every certificate of the server chain. BaresipKit uses it for SPKI SHA-256 pinning (`Core/src/bsk_tls.c`). Plain C types only, no OpenSSL types in the public API. | to be proposed |
| `0005-baresip-ice-module-events.patch` | baresip v4.9.0 | The ICE module logs state changes but emits no events, so an application cannot learn the ICE state or the selected candidate pair without parsing logs. The patch emits `module_event("ice", ...)` for gathering, checking, connected (with local/remote candidate types and addresses) and failed, keyed by the SDP media pointer so the application can map it to a call. | to be proposed |

| `0006-baresip-start-media-after-mnat-with-optional-menc.patch` | baresip v4.9.0 | When a media encryption is configured, `stream_mnatconn_handler()` only started the media encryption after the media NAT connected and never started audio or video. With optional SDES-SRTP that the peer declines, and ICE completing after the call was answered (typical for TURN relay), the call stayed silent: no RTP was ever sent. Found by the TURN relay integration stage. The patch starts the streams whenever they are ready; encryptions that wait for a secure state (DTLS-SRTP) are unaffected because `stream_is_ready()` still returns false until they are secure. | to be proposed |

| `0007-baresip-ice-turn-over-tcp-tls.patch` | baresip v4.9.0 | The ICE module allocated relayed candidates over UDP only, so `turn:...?transport=tcp` and `turns:` were unusable with ICE, which matters on networks that block UDP. The patch connects to the TURN server over TCP (and TLS for `turns:`, verified with the SIP TLS context), allocates the relay on that connection, forwards the component's outgoing packets through it with a UDP helper and injects relayed data back into the UDP socket, reusing the stream framing of baresip's `turn` module. When TURN runs over TCP/TLS the session uses the relay-only ICE policy, because host and server-reflexive paths cannot be assumed to work on such networks. | to be proposed |
| `0008-baresip-ice-restart.patch` | baresip v4.9.0 | A network change re-INVITEd ICE calls with the old credentials and candidates, which are bound to the previous network, so media did not recover. The patch adds an optional `restarth` hook to `struct mnat` and a public `call_restart_mnat()`. `call_reset_transp()` uses the hook when available: the ICE module creates new `ice-ufrag`/`ice-pwd`; if the local address changed it drops its STUN/TURN state, gathers again and the existing "media-nat established" path sends the re-INVITE once gathering completes, otherwise it keeps the gathered candidates and TURN allocations (TURN servers reject a second allocation from the same 5-tuple) and re-INVITEs right away; the connectivity checks start when the answer carries the peer's new credentials and are repeated up to five times, one second apart, if they fail, because a peer can still reject the first checks while it switches to its new credentials. An incoming offer with a new `ice-ufrag` restarts ICE on the answering side with new credentials and the already gathered host, server-reflexive and relayed candidates, so the answer is complete without waiting. Without negotiated ICE the call falls back to the plain re-INVITE. | to be proposed |
| `0009-baresip-video-set-bitrate.patch` | baresip v4.9.0 | baresip fixes the video encoder bitrate when the encoder is created, so an application cannot react to packet loss without renegotiating. The patch adds `video_set_bitrate()`, which stores the new target and passes it to the running encoder through the codec's update handler, and `video_bitrate()` to read it. The send pacer keeps the configured rate as its ceiling. | to be proposed |

## Verifying a patch

```bash
git -C <baresip checkout> apply --check Patches/0001-baresip-account-contact-uri-params.patch
git -C <baresip checkout> apply --check Patches/0003-baresip-avcapture-ios-screen-input.patch
```
